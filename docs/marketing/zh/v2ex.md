# V2EX 草稿（节点：分享创造）

**标题：** [开源] agent-guard：给 Kimi Code / Claude Code / Codex 装一个"行为熔断器"，专治 Agent 死循环烧额度

**正文：**

先讲个事故现场：上周一个无人值守的 CI 任务里，agent 对同一个 grep 命令连跑了 76 次——直到把整个 5 小时配额窗口烧穿。这不是我一个人的倒霉事，上游 issue 里挂着同型号的事故（kimi-cli #2142，最高纪录 112 次连发）。

监控类工具只能事后告诉你花了多少，我想要的很简单：**在烧穿之前拦住它**。所以写了 agent-guard：

挂在 CLI 官方的 hooks 系统上，分析每一次工具调用的行为模式：

- 同一调用指纹重复 N 次 → 阻断，把理由回喂给模型（"结果已在上下文里，别重跑"）
- A→B→A→B 振荡循环、参数不同但输出逐字节相同、同一文件反复改不收敛、一直读文件不动手——各有一个检测器
- 先软后硬：先往上下文注入警告让模型自我纠偏，不听才硬阻断；单会话干预超阈值直接保险丝断电，强制总结收尾
- 配额闸门理解订阅制：5h/周窗口 + 燃烧率外推，窗口耗尽前提前禁止派发子代理（可接官方用量 API 做精确计量）
- 完工闸门：模型说"测试全过"？查本地命令历史，没真跑过就打回去重跑
- 失败/中断自动存档"研究状态简报"，恢复会话时免重复探索
- CI 场景：`agentguard run` 受监督运行，硬性步数/时长上限 + 自动续跑，退出码区分正常/被干预

工程上几个点：纯函数分析器（可单测可移植）、fail-open（守卫自己挂了不影响 agent）、本地 SQLite、零守护进程零代理。136 个测试。

地址：https://github.com/shidesheng0218/kimi-guard
安装：`npm i -g @shidesheng0218/agentguard && agentguard install`

误报反馈欢迎：`agentguard feedback fp <id>`，反馈会喂给检测器校准。
