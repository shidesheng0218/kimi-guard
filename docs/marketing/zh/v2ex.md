# V2EX 草稿（v1.4.0，节点：分享创造)

**标题：** [开源] agent-guard：给 AI 编程 Agent 装的行为熔断器，防死循环烧额度，附碰撞测试场

**正文：**

事故现场：无人值守的 CI 任务里，agent 对同一个 grep 命令连跑 76 次，直到把整个 5 小时配额窗口烧穿。上游 issue 区同型号事故最高纪录 112 次连发——监控类工具只能事后告诉你花了多少，我想要的是**烧穿之前拦住它**。

agent-guard 挂在各 CLI 官方 hooks 系统上（Kimi Code / Claude Code / Codex / Gemini)，每次工具调用前过一遍纯函数分析器：

- 重复调用指纹、A→B→A 振荡、参数不同但输出（近）字节相同、同一文件反复改不收敛、只读不写的探索漂移
- 先软后硬：warn 注入上下文让模型自我纠偏 → 硬阻断并把理由回喂给模型 → 单会话干预超阈值直接保险丝，强制总结收尾
- 完工闸门：模型说"测试全过"？查本地命令史，没真跑过就打回去重跑
- 配额闸门理解订阅制：5h/周窗口 + 燃烧率外推 + 子代理权重，窗口耗尽前禁止派发（可接官方用量 API 精确计量）

几个我认为这次值得看的点：

1. **十秒自证**:`agentguard canary` 用真实 hook 路径发 3+1 发合成重复调用，现场展示第 4 发被拦——守卫类工具最大的问题是"它到底在不在干活"，这个十秒给出答案
2. **碰撞测试场**:`agentguard bench` 拿病理场景（循环风暴/假完工/上下文压力）给守卫自己打分，CI 里天天跑
3. **每周摘要**:`agentguard digest` 告诉你这周它拦了什么、估算省了多少请求——守卫最大的留存敌人是"无感知"，这是给"你一直在被保护"一个周期性确认
4. **工程取向**：全部 fail-open（守卫自己挂了 agent 照常工作）、本地 SQLite、零守护进程零代理、唯一 LLM 调用是可选的便宜模型单票否决（限额度、fail-closed)

地址：https://github.com/shidesheng0218/kimi-guard
安装：`npm i -g @shidesheng0218/agentguard && agentguard install && agentguard canary`

误报反馈欢迎：`agentguard feedback fp <id>`，反馈会喂给检测器校准。
