# V2EX 草稿（v1.9.0，节点：分享创造)

**标题：** [开源] agent-guard：给 AI 编程 Agent 装的行为熔断器，执行前拦截死循环，Agent 静默挂死也会告警

**正文：**

事故现场：无人值守的 CI 任务里，agent 对同一个 grep 命令连跑 76 次，直到把整个 5 小时配额窗口烧穿。上游 issue 区同型号事故最高纪录 112 次连发——监控类工具只能事后告诉你花了多少，我想要的是**烧穿之前拦住它**。

agent-guard 挂在各 CLI 官方 hooks 系统上（Kimi Code / Claude Code / Codex / Gemini)，每次工具调用前过一遍纯函数分析器：

- 重复调用指纹、A→B→A 振荡、参数不同但输出（近）字节相同、同一文件反复改不收敛、只读不写的探索漂移
- 先软后硬：warn 注入上下文让模型自我纠偏 → 硬阻断并把理由回喂给模型 → 单会话干预超阈值直接保险丝，强制总结收尾
- 完工闸门：模型说"测试全过"？查本地命令史，没真跑过就打回去重跑
- 配额闸门理解订阅制：5h/周窗口 + 燃烧率外推 + 子代理权重，窗口耗尽前禁止派发（可接官方用量 API 精确计量）

v1.9 补上了最后一个盲区——**停滞检测**。所有循环检测器都盯着工具调用，但停滞的 Agent（API 挂死、流断开）根本不产生调用，等于全盲。现在：监督模式下 Agent 静默超 N 分钟且没有工具在跑就告警（30 分钟的正常构建不会误报，挂死的 API 调用会）；纯 hooks 模式下会话恢复时补报。v1.8 还加了 webhook 通知：拦截/保险丝/停滞/每周摘要都能 POST 到 Slack/Discord/飞书桥——CI runner 和服务器上没有桌面，这是唯一能送到的通道。

几个值得看的点：

1. **十秒自证**:`agentguard canary` 用真实 hook 路径发 3+1 发合成重复调用，现场展示第 4 发被拦
2. **碰撞测试场 + 误报套件**:`agentguard bench` 双轴记分——病理场景要拦住，正常行为（读代码/收敛迭代/轮询）绝不误伤。误报套件上线第一天就抓到两个真误报
3. **每周摘要**:`agentguard digest` 告诉你这周它拦了什么、估算省了多少请求
4. **工程取向**：全部 fail-open（守卫自己挂了 agent 照常工作）、本地 SQLite、零守护进程零代理、221 个测试跑在 Ubuntu+Windows CI

和同类层的分工：TokenFuse 那类 LLM 代理管"这次调用花了多少钱"（美元熔断），我们管"这次工具调用该不该发生"（语义行为）；转录监视类工具只能事后告警——转录是执行后才写的，Telegram 响的时候额度已经烧完了。

地址：https://github.com/shidesheng0218/kimi-guard
安装：`npm i -g @shidesheng0218/agentguard && agentguard install && agentguard canary`

误报反馈欢迎：`agentguard feedback fp <id>`，反馈会喂给检测器校准。
