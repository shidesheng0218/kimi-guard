# 掘金 / 知乎 长文草稿（v1.4.0)

**标题：** 我让 AI 编程 Agent 烧穿了 5 小时配额——然后我给它写了个熔断器（开源）

**开头：**

上周三凌晨，一个无人值守的 CI 任务里，我的 Kimi Code agent 卡死了。不是崩溃，是更贵的那种卡死：同一条 `grep` 命令，连跑 76 次。每次返回一样的结果，模型看完，再跑一次。没有人按 Ctrl+C，因为没有人。

等我早上看到的时候，5 小时配额窗口已经烧穿了。

上游 issue 区一查，这不是个例：kimi-cli #2142 里挂着同型号事故，最高纪录同一命令连发 112 次。而且这类问题天然无法靠"步数上限"解决——机械计数器只知道跑了多少步，不知道这些步是不是同一个动作的空转。

**问题分析（知乎加深这段）:**

Agent 失控有几种可识别的行为指纹：

1. **精确重复**：同一 `(工具, 参数)` 反复调用——结果明明已在上下文里
2. **振荡循环**：A→B→A→B 换着来，检测周期更隐蔽
3. **无信息增益**：参数换着花样改，输出逐字节或近似相同——在错误的方向上疯狂尝试
4. **编辑抖动**：同一个文件改了 10 次不收敛，是在猜不是在修
5. **探索漂移**：读了 20 个文件一行代码没写

以及一个更贵的：**假完工**。模型最后说"测试全部通过"，但整个会话里根本没跑过测试命令。

**方案：**

agent-guard 挂在 CLI 官方 hooks 系统上（Kimi Code / Claude Code / Codex / Gemini 都有），每次工具调用前过一遍纯函数分析器，按严重度分级干预：

- warn：往上下文注入一条提醒，让模型自己纠偏（大多数循环到这里就结束了）
- block：exit 2 阻断调用，阻断理由作为纠正反馈回模型
- kill switch：单会话干预超阈值，封锁全部工具，命令模型总结收尾

完工闸门是确定性的：完工声明必须匹配本地记录的"真跑过测试"的证据，否则触发纠正轮重跑。

**这次更新里我认为真正值得说的三件事：**

**十秒自证**。守卫类工具最尴尬的问题是"它到底在不在干活"——装了、没拦过、是 agents 都乖还是没接上？`agentguard canary` 用真实的 hook 路径发 3+1 发合成重复调用，现场展示第 4 发被拦截、并给出模型收到的完整阻断理由。10 秒，从"祈祷它工作"到"看着它工作"。

**碰撞测试场**。我给守卫自己建了个考场：`agentguard bench` 用六个病理场景（循环风暴、假完工、上下文压力、思维空转、步数上限、无增益空转）给守卫打分，0-100。CI 里天天跑，分数挂在 README——**它每天用自己的失控案例自证清白**。

**每周摘要**。守卫做得越好越无感，无感就没有习惯，没有习惯就会被遗忘。`agentguard digest` 每周告诉你：这周拦了什么、按启发式估算省了多少请求、配额水位多少、哪个检测器误报偏多该调阈值。配一条 cron，每周一早上弹桌面通知——不用任何守护进程。

**工程取舍：**

- 全部 fail-open：守卫自己出错，agent 照常工作。守卫绝不能成为单点故障
- 分析器是纯函数，179 个测试
- 状态存本地 SQLite（node:sqlite），零守护进程、零代理、不碰账号
- 配额计量理解订阅语义：5h/周窗口、预留余量、燃烧率外推、子代理权重；还能接官方用量 API 做精确计量
- 唯一的 LLM 调用是可选的完工否决票：便宜模型、单票 8 token 上限、每会话限 3 票、任何失败一律维持拦截（fail-closed)

**收尾：**

安装：`npm i -g @shidesheng0218/agentguard && agentguard install && agentguard canary`
仓库：https://github.com/shidesheng0218/kimi-guard （MIT)
